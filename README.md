### 피규어 이벤트 운영 설정

개봉 영상은 전체 다운로드 후 Blob URL로 재생하여 Range 요청을 지원하지 않는 로컬 서버에서도 드래그 탐색이 가능하도록 한다. 자동 오픈은 정상 `play()` 재생을 사용하고 `ended` 이벤트에서 결과 화면으로 전환한다. 드래그로 끝까지 펼친 경우에는 화면에 이미 펼쳐진 마지막 프레임을 그대로 두고 즉시 결과 화면으로 전환하며, 마지막 프레임에서 `play()`를 호출하지 않는다. 끝 근처 탐색 위치를 `duration`으로 맞추는 브라우저에서 `play()`가 개봉 영상을 처음부터 다시 재생하는 문제를 막기 위해서다. 재생 실패 시 같은 당첨 결과로 재생을 재시도하며 재고를 추가 차감하지 않는다.

메인 영상은 관리자가 업로드한 대기 영상만 원본 비율로 중앙 표시한다(업로드가 없으면 영상 없이 기본 그라데이션). 영상 비율이 화면과 다를 때만 같은 영상을 확대한 사본을 뒤에 깔고 `backdrop-filter` 베일로 흐려 여백을 채운다. 영상에 `filter`를 직접 걸면 iOS Safari에서 `object-fit`이 깨져 원본 크기로 좌상단에 그려질 수 있어 이 방식을 쓴다. TOUCH 버튼은 텍스트 폭에 맞춰 중앙 정렬한다. 소환서 12개는 화면 높이에 맞춰 태블릿 4×3, 좁은 화면 3×4로 배치한다. 결과 카드는 화면 높이에 맞춰 확대했다.

소환서는 사운드 포함 `Sacred Scroll Reveal.mp4`(30fps)를 두 구간으로 나눈다. `03:10`은 3초 10프레임으로 해석하며, 해당 프레임까지는 `sacred-idle.mp4`를 반복 재생하고, 같은 구간의 사운드는 `sacred-idle.wav`를 Web Audio로 디코딩해 영상 위치에 맞춰 반복 재생한다(드래그 사운드와 같은 경로). Web Audio를 쓸 수 없으면 영상 자체의 오디오 트랙을 켠다. 관리자 음소거를 따른다. 터치하면 원본 `03:11`(프레임 인덱스 101, 약 3.367초)부터의 `sacred-open.mp4`를 표시하고, 드래그 진행률 0~100%를 개봉 영상 첫 프레임~마지막 프레임에 직접 매핑한다. 오른쪽으로 진행·왼쪽으로 역행하고, 중간에 놓거나 취소하면 재고 차감 없이 대기 루프로 돌아간다. 끝까지 진행하고 손을 놓으면 추첨을 한 번 확정한다. 원본은 보존하며 최적화본 생성은 `scripts/prepare-sacred-scroll.py`를 사용한다.

드래그 사운드는 `sacred-open.wav`를 Web Audio로 디코딩하여 해당 재생 위치의 최대 0.1초 구간을 짧게 겹쳐 재생한다. 왼쪽 드래그는 뒤집은 오디오 버퍼를 사용한다. 움직임이 멈추면 새 소리를 만들지 않으며 마지막 짧은 소리만 종료된다. 취소·화면 이탈·음소거 시 중지한다. 자동 오픈은 드래그용 짧은 소리를 중지하고 같은 sacred-open.wav 버퍼를 정상 속도로 재생한다. 영상 내장 오디오는 끄며, 버퍼가 준비되지 않았을 때만 내장 오디오를 대체 경로로 사용한다. 소환서 화면에 있는 동안(대기 루프 포함) BGM은 기존 볼륨의 25%로 낮추고 화면을 벗어나면 복귀하며 관리자 음소거를 따른다. Web Audio를 사용할 수 없는 환경에서도 자동 오픈의 영상 오디오는 사용할 수 있다.

영상 마지막 0.3초 동안 전체 화면을 흰색으로 덮는다. 드래그를 되돌리면 흰색도 줄어든다. 영상 종료 시 완전한 흰색 아래에서 결과 화면으로 전환하고 0.4초 동안 흰색을 걷어낸다. 이전 CSS 종이 효과는 사용하지 않는다.

피규어(제라투) 당첨이면 흰색 아래에서 결과 화면 대신 전체 화면 소환 연출을 먼저 보여준다. 작업 폴더의 `zeratu summon_34.mp4`(원본)를 `scripts/prepare-zeratu-summon.py`로 H.264 `zeratu-summon.mp4`와 포스터로 변환해 동봉한다. 원본(1080×1440)은 위·아래 112행이 검은 띠라 1080×1216으로 잘라낸다. 오버레이는 메인 대기 영상과 같은 방식으로 원본 비율 클립을 중앙에 두고 같은 영상을 확대·블러 처리해 여백을 채운다. 사운드는 같은 원본에서 뽑은 `zeratu-summon.wav`를 Web Audio로 디코딩해 영상이 실제로 재생되기 시작하는 순간(`playing`)부터 영상 위치에 맞춰 재생하고, 버퍼링으로 멈추면 함께 멈춘다(드래그·대기 사운드와 같은 경로). Web Audio를 쓸 수 없으면 영상 자체의 오디오 트랙을 켠다. 관리자 음소거를 따른다. 영상이 끝나면 0.4초 페이드로 걷히면서 기존 결과 화면(번개·색종이·팡파르)이 나온다. 재생 실패나 종료 이벤트 누락(영상 길이 + 3초) 시에도 결과 화면으로 넘어간다. 연출 중에는 처음으로 돌아가기와 유휴 복귀를 막는다. iPad에서 자동 오픈처럼 사용자 제스처 밖에서 시작되는 재생에도 소리가 나도록 소환서 화면에 들어갈 때 영상 요소를 한 번 미리 로드한다. 참가상은 흰색에서 바로 결과 화면으로 간다.

화면 구성: 메인 화면은 로고 락업만 두고 이벤트명 텍스트와 아레나 배경(이미지·기본 루프 영상)을 쓰지 않는다. 소환서 선택 화면의 부제는 없다. 소환서 열기 화면의 제목은 "소환서를 펼쳐주세요 · N번 소환서"를 같은 글꼴·크기로 한 줄에 표시하고, 소환서 영상은 소환서 선택 카드와 같은 보라 그라데이션·보라 테두리·글로우 박스 안에 정사각형으로 놓는다. 박스 아래에는 `drag-arrow.svg` 핸들이 트랙을 따라 왼쪽에서 오른쪽으로 반복 이동하는 드래그 안내 애니메이션과 "스크롤을 오른쪽으로 밀거나 자동 오픈 버튼을 클릭하세요" 문구를 둔다(드래그 중·개봉 중에는 숨김, 감속 모션 설정 시 정지). 결과 화면 배경은 다른 피규어 화면과 같은 아레나 이미지를 쓴다.

- 관리자 진입은 기존처럼 메인 좌상단을 3초 안에 5회 터치하고 PIN 입력(초기 0000).
- IP·상품에서 상품 종류를 **피규어 / 참가상**으로 지정하고 초기 수량과 실제 잔여 수량을 설정한다. 새 설치의 초기 재고는 0이다.
- 기본은 **재고 비례 추첨(OFF)**이다. 전체 IP의 노출 피규어·참가상을 합쳐 잔여 수량에 비례해 선택한다. 한 종류가 소진돼도 다른 종류로 계속 진행하며, 모든 노출 경품이 소진되면 종료한다.
- 설정의 **피규어 당첨 확률 사용**을 ON으로 바꾸면 별도 확률(0~100%)을 적용한다. **추첨 방식 저장**을 눌러 적용한다. 이때 피규어 당첨 여부를 먼저 결정하고, 해당 종류 안에서 잔여 수량에 비례해 선택한다. 초기 확률 표시값은 10%이며 OFF 동안은 적용하지 않는다.
- ON에서 피규어 소진 시 참가상만 지급하며, 참가상 소진 시 중지한다(피규어 확률 100% 제외). OFF로 전환하면 입력한 확률은 보존하고 재고 비례 방식으로 돌아간다. 전환은 재고·기존 로그를 변경하지 않는다. 스위치 필드가 없는 이전 설정도 OFF로 시작한다.
- 두 모드 모두 번들은 하위상품까지 재고 비례로 선택하고, 소환서 번호는 확률에 영향을 주지 않는다. 기존 쿨다운·행운상은 적용하지 않는다. 새 로그에는 적용한 추첨 방식과 ON일 때의 설정 확률을 함께 기록한다.
- 각 상품의 이미지와 함께 **상품 영상**(결과에서 무음 반복), **클릭 팝업 영상**을 설정할 수 있다. 팝업 동안 자동 복귀를 멈추고 닫은 뒤 다시 5초를 센다. 상품 영상은 60MB 이하.
- BGM은 기존 화면별 3슬롯(대기/선택/뽑기) 전환 외에 설정의 **재생 방식**에서 **한 곡 연속 루핑**을 고를 수 있다. 연속 모드에서는 **연속 재생 곡**으로 고른 슬롯 한 곡이 화면이 바뀌어도 끊기거나 다시 시작하지 않고 이어지며, 소환서 화면·개봉 연출 중 BGM 볼륨 자동 감소(25%)와 음소거는 그대로 적용된다. 고른 슬롯에 곡이 없으면 무음이다.
- 대기 영상, BGM, 효과음, 재고 편집, CSV, 백업·복원은 기존 기능을 재사용한다. NPC·라인업 등 이전 설정은 보존하지만 새 참가자 흐름에는 표시하지 않는다.
- 새 추첨은 재고와 로그를 `figure-draw.draw-state.v1`에 한 번에 저장한 후 연출한다. 저장 실패 시 추첨을 확정하지 않는다. 이전 개별 저장 키도 초기 로드에서 읽을 수 있다.

localStorage 키와 IndexedDB 이름, 서비스 워커 캐시 이름은 기존 앱과 분리했다. 새 서비스 워커는 자기 앱 접두사의 캐시만 정리한다. 기존 앱의 구형 서비스 워커는 같은 origin의 다른 캐시를 삭제할 수 있어, 두 앱을 같은 브라우저에서 함께 운영하기 전 기존 앱 쪽 정리 범위도 확인해야 한다.

- `app/`: PWA 본체와 동봉 에셋
- `app/figure.js`, `app/figure.css`: 소환서 흐름 및 기존 백오피스 확장
- `app/draw-engine.js`: 종류별 확률·재고 추첨 규칙
- `index.html`: 앱으로 이동하는 루트 진입점
- `scripts/prepare-*.py`: 원본 영상에서 앱용 최적화본을 만드는 스크립트(Pillow, imageio-ffmpeg)
- `KUJI-REFERENCE-ANALYSIS.md`: 기존 코드 분석과 후속 보완 사항
- `WORKLOG.md`: 날짜별 작업 일지(무엇을 왜 바꿨는지)
- `.nojekyll`: GitHub Pages 정적 파일 배포

GitHub Pages는 main 브랜치 루트를 배포한다. 빌드 및 패키지 설치 과정은 없다.

로컬 확인: 프로젝트 폴더에서 `python -m http.server 8000` 실행 후 `http://localhost:8000/app/` 접속. 현재 베이스는 localhost에서 서비스 워커를 등록하지 않으므로 오프라인 설치 검증은 배포 주소에서 한다.

## 원본 에셋

작업 폴더 루트의 PNG 원본과 `reference-kuji/`는 로컬 참조용으로 Git에서 제외했다. 특히 100MB를 넘는 원본이 있어 그대로 일반 Git 커밋에 포함하지 않는다. 앱용 최적화본은 `app/assets/figure/`에 포함되어 있다. 미참조 이전 시안 scroll-looping-2.mp4 및 scroll3-idle.mp4 / scroll3-open.mp4 / scroll3-poster.jpg는 로컬에만 남겨두고 커밋하지 않았다. `.kuji` 운영 백업도 Git에서 제외한다.

## 운영 전 검증

행사 수량·확률·참가상 콘텐츠 입력과 실기기 터치·오디오·오프라인·백업 복원 확인이 필요하다. 기존 앱 폴더의 README는 과거 쿠지 운영 가이드로, 새 동작은 이 문서와 실제 코드를 기준으로 확인한다. 기존 관리자 편집의 저장 실패 처리와 전체 백업 복원의 사전 검증은 추가 보완 대상이다.

검사: `node scripts/test-figure.cjs`. DOM 흐름 검사: 임시 `.tools/`에 jsdom 설치 후 `node scripts/test-figure-dom.cjs`. 에셋 준비 스크립트는 Pillow와 imageio-ffmpeg를 사용하며 원본을 덮어쓰지 않는다. 참조 영상 4~11초를 확인해 선택→개봉→금빛 연출→결과 순서를 반영했으며, 펼침은 실제 MP4 프레임 탐색을 드래그 진행률에 매핑하고 흰색 전환 효과를 함께 적용한다.

### v16 자동 오픈 배속 검토

자동 오픈에만 1.8배속을 적용했다. 분리된 Web Audio도 같은 재생률로 맞추며 버퍼링 후에는 영상 위치에서 다시 시작한다. 내장 오디오 대체 경로도 음높이 보정을 해제해 같은 배속 효과를 따른다. 종료는 기존 ended 이벤트로 처리하고 추첨·재고 확정 로직은 바꾸지 않았다. 마지막 0.3초 흰색 전환 구간은 실시간 약 0.167초로 짧아진다. 전체 행사 처리 시간 절감률은 선택·상품 수령·당첨 연출 시간에 따라 달라진다. iPad에서 프레임 끊김, 소리 동기화, BGM 25% 유지/복귀와 자동 오픈 후 드래그를 확인해야 한다.

 v16 검증 결과: test-figure / test-figure-dom / test-scroll-audio / test-audio-mix / test-figure-browser 및 git diff --check 통과. 실제 Chrome 자동 오픈 playbackRate=1.8, BGM RMS 0.137708 → 0.034414(약 25.0%) → 0.138314, 효과음 0.282204 확인. iPad 결과는 미확인.
