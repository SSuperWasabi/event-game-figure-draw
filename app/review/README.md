# iPad regression comparison

Snapshots generated by `node scripts/prepare-version-review.cjs` from v8 `7ee9060`, v9 `ec217dc`, and v11 `b49b159`.

Production app entry files are not changed. Snapshot differences from each commit are limited to URL routing, a separate localStorage namespace seeded from production settings/state, read-only shared media access, disabled service worker registration, and diagnostic controls. The existing service worker may still control the pages, so this compares version code under the current cache environment, not historical service-worker state. The v8 bundled idle clip is included because production v9 removed it.

Browser verification: all three snapshots completed actual MP4 playback and one draw while leaving production draw-state unchanged in Chrome. This is not iPad verification.

On the affected iPad, compare v8 first, then v9, then v11 using the same uploaded media. Save diagnostics on failure. Record loop playback, drag seek, and automatic reveal separately. If v8 works and v9 fails, isolate the v9 backdrop/media-lifecycle changes before touching the scroll controller again. If v8 also fails, investigate shared device/media/cache conditions rather than assuming the version number is the cause.
